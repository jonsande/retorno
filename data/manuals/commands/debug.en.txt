Purpose
- Operator/developer control surface for deterministic testing and scenario resets.

Operational behavior
- `debug god on|off|status` controls session-only damage protection. Activation requires DEBUG; off and status work in either mode.
- Protection blocks new hull/system wear, harmful drone radiation dose, drone integrity damage and operational battery drain. Existing damage, disabled drones and empty batteries are not restored.
- `debug off`, a new debug session, scenario reset and loading a save leave god mode off. Repeating `debug on` within the same session preserves its state.
- Ambient/internal radiation readings remain real. Ordinary bay maintenance and requested repairs still operate; resources, power limits, job failures, discovery and physical durations keep their normal rules.
- `debug on` stops automatic time; `wait N` advances manually using the existing one-second steps. God mode does not change travel or job times.
- `debug on|off` toggles debug mode and auto-tick control.
- SANDBOX and FAST_SANDBOX are initially intended exclusively for debugging and design testing. FAST_SANDBOX recovers ECHO_7 completely and starts in orbit with fully repaired systems and drones in the bay.
- `debug scenario ...` resets world state to preset.
- `debug seed <n>` sets RNG seed before the historical universe is fixed by generation or saving. Later changes require a new scenario.
- listing commands expose internal debug registries.
- `debug galaxy` prints galactic position, sector-neighborhood coherence, and procedural-radiation distribution.
- `debug galaxy map <scale>` renders the galaxy ASCII map at selected scale using all loaded nodes.
- `debug worldgen sector <sector_id>` materializes the requested sector through normal worldgen and dumps archetype, hubs, node list, overlays, and physical vs known links for that sector.
- `debug graph all` dumps the full currently materialized graph, including sector summaries, node summaries, and physical edges.
- `debug add scrap <amount>` injects scrap directly into cargo inventory.
- `debug add module <module_id> [count]` injects one or more modules from the full catalog (ship and drone scope).
- `debug add drone[s] [count]` creates docked drones in the bay for rapid testing.

Usage notes
- Intended for testing and balancing, not diegetic normal play.
- `debug add ...` operations require DEBUG mode enabled (`debug on`).

Related commands
- `wait <seconds>`, `status`, `jobs`
